# Architecture — M1 development

Scoria retains iPlug2/IGraphics, C++17, the iPlug2OOS build conventions and the original identities: `TlDs` manufacturer, `Scor` product, AU type `aufx`, `com.TalosDSP.vst3.Scoria` and `com.TalosDSP.audiounit.Scoria`. Version 0.0.3 is the M1 acceptance candidate. Only native VST3 and macOS AUv2 are built. GUI remains 800×520 with PEDALS / AMP / CAB / FX.

## Audio path

`AudioEngine` applies input trim → envelope gate → frequency-shaped overdrive → NAM → direct FIR → output level. Global bypass crossfades to a latency-aligned original input and settles to an exact delayed dry copy. Each implemented stage has an independent smoothed bypass. Controls use 10 ms ramps; gate attenuation uses its own 0.5 ms attack and user release, with 6 dB hysteresis. Gate threshold is dBFS; release is ms. The original overdrive uses bass attenuation before soft clipping, four interpolated substeps, post-clipping tone filtering and a 15 Hz DC blocker. It is inspired by a tight guitar boost, not an exact hardware emulation. Oversampling is limited to this stage; it reduces but does not eliminate aliasing. No synthetic waveshaper substitutes for NAM.

Input and output trims have independent ramps on opposite sides of the nonlinear chain. The engine uses fixed 256-frame scratch arrays and accepts arbitrary host block lengths by splitting internally. Stereo uses two independent NAM, gate, overdrive and FIR states; channels are never summed. Mono processing occurs once, then duplicates to stereo output. Both inputs are read before writes, including in-place buffers. Supported layouts remain 1→1, 1→2, 2→2. Invalid layouts silence outputs; missing stereo right input duplicates left. Nonfinite inputs/outputs and extremely small internal states are zeroed. NAM rate adaptation introduces 127/0/186/196 host samples at 44.1/48/88.2/96 kHz. The disabled-amp path and global dry path have matching fixed delays. Filter phase and the response within the captured model/IR are not additional host buffering latency.

## NAM and assets

`NamAmplifier` wraps pinned NAM Core v0.5.4. A static object-library integration retains upstream architecture registration objects. The selected upstream compiles as C++17, so the project standard has not changed. Fast-math is not enabled. NAM is prepared with a 256-frame maximum, prewarmed off-thread, and run as two mono instances. Both audited models expect **48 kHz**. At other supported host rates, an original rational polyphase FIR converts host→48 kHz→host. It uses persistent integer phases, normalized four-term Blackman-Harris windowed-sinc coefficients, 128-sample support, and a 0.94 Nyquist cutoff scaled for downsampling. Fractional output-filter delay makes total delay integral; four host samples of FIFO padding cover rate-count scheduling. 48 kHz bypasses these converters entirely. Coefficients allocate only during preparation. Fixed histories, native scratch and output FIFOs cover the maximum 256-frame internal chunk at all four supported ratios. Unknown host rates are rejected explicitly.

`ModelRegistry.h` is append-only: legacy RiffSmith ID `0x52464431`; Lum Herbert 4 ID `0x48425434`. Each entry records filename, exact SHA-256, license, native rate and cabinet metadata. Validation hashes the exact bytes subsequently parsed. Only audited models can reach NAM's parser. The new default is Lum's full WaveNet inside a SlimmableContainer; no live slimming is exposed. RiffSmith is retained unchanged for old projects.

Tight Rhythm enables the amp-only Herbert capture and Jester Cookie Monster IR. The legacy RiffSmith capture includes a cabinet, so its preset disables the separate IR. State restoration preserves explicit user choices, including intentional double-cab processing; the CAB page warns about the legacy capture.

`WavImpulse` decodes mono little-endian PCM16/24/32 or float32 RIFF WAV off-thread. It rejects invalid/truncated/nonfinite/unsupported inputs. IR preparation uses a 65-point windowed-sinc resampler when rates differ, with impulse-area scaling. It keeps the first 42.67 ms (maximum 4096 taps) and fades the last 128 taps to omit the long room tail. No peak normalization occurs. `Cabinet` uses a preallocated circular history and direct convolution. This is intentionally simple and zero-buffer-latency; benchmark costs before increasing IR length.

## Ownership and real-time contract

`AssetLoader` owns a preparation worker. Host reset changes a single atomic configuration/epoch request; it does not construct or reset NAM. The worker loads and prewarms a complete candidate. An atomic pending pointer transfers exclusive ownership to the audio consumer at a block boundary. The previous active object moves into a single retirement slot; the worker deletes it. The audio consumer refuses another handoff while retirement is occupied. Stale generations never process. All pointer atomics and request types must be lock-free. In-progress preparation can finish after a new request but is discarded by generation checking. Asset arrival fades in over 10 ms. During preparation an enabled unavailable amp/cab is silent, not a fake pass-through effect.

No I/O, allocation, model construction, mutex wait, logging, UI call or heavy destruction occurs in Scoria's callback. NAM's fixed container selection only performs an atomic index read; no live slimming is exposed. Worker polling sleeps outside audio; no audio-thread wake-up primitive is needed. Stop audio before destroying the plugin: destruction joins the worker and reclaims the remaining objects. Host teardown can wait for preparation; it never happens in `ProcessBlock`. Live resets/model switches may temporarily mute while preparation completes; gapless model switching is not implemented. Offline host lifecycle reset waits for worker preparation (bounded to 10 seconds), before any ProcessBlock call. A guarded build-local VST3 wrapper patch publishes offline mode during setupProcessing rather than waiting until the first process call. No callback waits, loads, or destroys models. A forced reset requests fresh NAM/resampler/FIR state for deterministic renders.

## Parameters and state

`Parameters.h` centralizes names, ranges, defaults and stable IDs. IDs 0/1/2 remain input/output/global bypass; IDs 3–15 append gate, overdrive, amp and cabinet controls. ID 16 appends the audited model selector. IR selector 0 is None (dry); value 1 maps to `jester-cookie-monster-v1`. Tight Rhythm and Legacy development rig are the two factory presets. Disabled future effects have no fake automation controls.

Schema 3 stores int32 version, uint32 model/cab/preset IDs, then 17 doubles. Preset IDs are 0 legacy / 1 Tight Rhythm. Version 2 retains its 16 values and selects RiffSmith; version 1 retains its three values. `State.h` validates a candidate fully before committing values. Version 1 restores its original three values and bypasses all new effects, preserving M0 session sound. Unknown IDs/versions, nonfinite/out-of-range values and truncation are rejected. State remains little-endian like M0; supported native architectures are little-endian. GUI tab selection is transient. Framework parameter reads are lock-free, block-granular and individually atomic; simultaneous valid multi-parameter changes are not one atomic audio snapshot.

A build-local copy of the pinned iPlug2 AU wrapper fixes two state issues: preset mutation before validation, and testing a negative decode return as a boolean success. `cmake/AuStatePatch.cmake` requires the expected upstream code and fails configuration if it changes. Upstream source checkouts remain untouched. AU regression tests cover the actual adapter.

Complete assets and their licenses are copied into each bundle's `Contents/Resources/assets`. iPlug2 resolves that installed resource directory; no runtime source/build directory is compiled into the plugin. CMake verifies source and packaged manifest hashes and fails when required assets are missing or altered.
